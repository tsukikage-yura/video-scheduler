# 音乐 → 视觉映射（Music-Visual Mapping）

> video-scheduler v0.1.0 · 输入含音频时加载。**为什么存在**：调度器曾只做"抓节拍卡点 + 用封面"，
> 把音乐降级成节拍器——节拍是音乐最浅的一层，只卡点 = 播放器式画面。
> 本文件给出**分层提取方法 + 映射规则**，让音乐真正驱动演出。

---

## 0. 硬规则：禁用封面作为风格来源

```text
❌ 封面 / 专辑图 不作为风格来源
   · 它是唱片工业的营销产物，常与歌的情感内核无关；
   · 它会【锚定】判断：看到封面就顺着它做，放弃从歌词/音乐推导；
   · 最坏情况：变成"给封面配动画"，不是"为歌做 MV"。
✅ 风格来源 = 歌词意象（§1.2 意象分析）+ 音乐数据（本文件）
例外：用户明确说"按封面风格做" → 记为锁定决策，可例外。
```

---

## 1. 提取优先级（先实测，再估算）

```text
measured onset / beat        ← 最可信
      ↓
measured features（chroma / 频谱 / 能量）
      ↓
waveform / envelope
      ↓
estimated timing
      ↓
nominal BPM only as fallback ← 最不可信，仅兜底
```

**本机可用工具**：librosa 1.0 + numpy + scipy + soundfile + ffmpeg（已验证）。
优先用实测数据，绝不"凭 BPM 猜时间"。

---

## 2. 四层提取（治"只会抓节拍"）

### L1 节拍层（基础，最常被误当成全部）

```text
· beat / onset         → 卡点、脉冲、撞击
· downbeat（小节线）   → 段落内的强动作、构图切换
· 拍号与重音           → 强拍给强动作，弱拍给微动
· 节奏密度曲线         → 每秒 onset 数：密度高=紧张，低=舒缓
· 切分 / 三连音        → 非规则节奏 = 不安 / 摇摆感
· tempo curve          → 渐快/渐慢（rubato）= 情绪爬升
```

**注意**：这一层只做"什么时候动"，不做"动什么"。只有 L1 = 卡点播放器。

### L2 结构层（决定全片骨架）

```text
· 段落切分（intro/verse/chorus/bridge/outro）→ 每段一个视觉世界/局部风格
· 自相似矩阵（SSM）  → 副歌重复了几次？哪两段是同一段？（重复段复用母题）
· 能量弧（长窗 RMS） → 整片情绪起伏曲线（先画弧再排镜头）
· 静音/留白段        → 呼吸位（负空间、衰减、让画面停）
· novelty 峰值       → 结构转折点（换场景/换风格的自然位置）
```

### L3 音色层（决定质感与色彩）

```text
· 调性 / 调式（大调 vs 小调）→ 情绪基调：大调偏明亮，小调偏暗
· 和弦进行 / 和声变化点      → 视觉转折点（和声一变，画面可随之一变）
· 频谱质心（brightness）     → 高频多=明亮轻快，低频多=厚重压抑
· 频谱通量                   → 音色变化速率（变化快=画面躁动）
· chroma 分布                → 定调性色彩（可选：把主音映射到色相）
```

### L4 分轨层（最强，但需工具支持）

```text
· 人声分离（vocal / instrumental）→ 人声驱动歌词画面，伴奏驱动背景
  本机无 demucs/spleeter，可用 librosa HPSS 做谐波/打击分离（弱化版）；
  有条件时优先用专业分离工具。
· 鼓组分离（kick / snare / hihat）→ 分别驱动不同视觉元素（见 §3 映射表）
· 人声起止检测  → 唱到哪句、何时换气（与词级时间轴配合）
· 人声音高曲线  → 上扬/下坠驱动视觉升降
```

## 3. 映射表：音乐特征 → 视觉参数

**原则：映射到参数，不是整场戏。** 音乐特征驱动"某个参数怎么变"，不是"整段换成什么"。

```text
kick        → 尺度脉冲（scale impulse）
snare       → 光标 / 文字闪动
hihat       → 细微抖动 / 高频粒子
bass        → 形变幅度（deformation amplitude）
high freq   → 精细抖动 / 粒子活跃度
energy      → 密度 / 亮度
silence     → 衰减 / 负空间
onset 密度  → 切换频率（密=快切，疏=长镜）
段落转折    → 场景/风格切换点
调性明暗    → 整体色温与对比
频谱质心    → 画面明度与锐度
```

**用衰减包络，不要单帧尖峰**——一击即消的尖峰看起来像故障，衰减才有物理感。

---

## 4. 歌词与音乐是两套时间源（不要互相吸附）

- 歌词时间来自实测的 LRC / 逐词时间轴；
- 节拍/onset 来自音频分析；
- **绝不把一套重采样到另一套的网格上**——把歌词时间吸到固定 BPM 上，看着整齐，实际唱晚了；
- 词级画面与节拍冲击共用一条时间轴时，以**实测词时间**为准，节拍只做冲击辅助。

---

## 5. 反例（这些就是"音乐处理不好"的样子）

```text
✗ 只卡节拍：每一拍动一下，画面变成节拍器；
✗ 只用 BPM：全片匀速卡点，段落结构、情绪弧全丢；
✗ 用封面定风格：变成"给封面配动画"；
✗ 音乐特征驱动整场戏：一有鼓点就整屏换场景（应该只驱动参数）；
✗ 单帧尖峰：一帧爆闪，没有衰减，像渲染错误；
✗ 歌词吸到 BPM 网格：整齐但唱晚了。
```

## 6. 歌词是事件，不是字幕

> ⚠️ **最高频的退化（真实事故）**：除动画10 外，后续项目都把歌词做成了**静态字幕层**——
> 歌词只是"贴在画面底部的文字"，不参与演出。动画10 的做法是**歌词本身就是动画**。

### 6.1 歌词必须"动"，而且要在三处动

```text
① 入场要动：逐词（不是整行）——每个词有自己的时间窗
   配方（动画10 实测）：easeOutCubic + 位移 46px + 缩放 [1.10,1.03]→1.0 + alpha 淡入
② 在场要动：唱到的词与未唱的词状态不同（变色/点亮/放大/加粗）
   + 可加"呼吸"（当前词轻微缩放脉动）
③ 退场要动：唱完的词不能僵在原地（淡出/上移/变暗/让位给下一句）
```

### 6.2 歌词的"画面感"手法（动画10 实测有效）

```text
· 套印错位重影：ghost 色偏移 (-7,-7) 打底，主色压上 → 印刷/手工感
· 逐词错相位：每词入场时间不同（T0 + 词序号 × GAP），形成"一串词逐个落下"
· 字号自适应：fitSize(文本, 目标宽度) —— 长句自动缩小，保持排版整齐
· 颜色随段落变：lyricFg(t) 按时间段切换前景色（与背景明暗呼应）
· 中文/英文分层：英文逐词（主歌词），中文整体打字机（typed）—— 两种语言不同处理
```

### 6.3 硬规则

```text
❌ 禁止：歌词只是"底部静态文字"或"整行淡入淡出"
✅ 要求：歌词至少满足"入场逐词 + 在场状态区分 + 退场处理"三条
✅ 更强：歌词与画面主体互动（词出现时画面元素响应：物体被"说出"、场景随词切换）

审计清单追加一项：
□ 歌词动了（逐词入场 + 唱到状态区分 + 退场）—— 不是静态字幕
```

歌词可以控制：场景转场 / 命令 / 状态变化 / 对象生灭 / 拓扑变化 / 排版 /
标签 / 错误 / 测量值 / 类对话 UI。

```text
歌词含义 → 操作 / 关系 / 状态 / 测量 → 视觉行为
```

实际歌词文本是用户权威来源；同步重要时**不要擅自改写歌词**。

## 7. 交付：音乐分析落盘（可审计）

分析结果必须落盘成结构化数据（如 `audio_features.json` / `beats.json`），字段建议：

```text
duration, sr, bpm, beat_count, beats[], downbeats[],
onset_count, onsets[], novelty_peaks[], quiet_regions[],
sections[]（段落切分）, key_guess, chroma_mean, spectral_centroid,
env（能量包络，含采样率 env_hz）
```

**为什么落盘**：调度器要按它切段/派活，成员要按它做演出，审计要能核对——
"模型看过就忘"等于没分析。
