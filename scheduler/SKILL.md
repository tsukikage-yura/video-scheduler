description: The scheduler (orchestrator) skill for time-driven videos of any kind. One main agent plays the scheduler: first UNPACKS the user message into structured assets (intent, dependency fill, style/anim/camera design via self-judged candidates), then SCHEDULES worker teammates on a 15-slot pool with isolated read-only asset grants (elements first — complex/reusable pieces are built and approved before shot production), audits their numbered outputs, and splices the film. # Video Scheduler — 调度器 Skill

> ⚠️ 发布声明：本版未经过任何验证；最佳运行环境是 DSH（**DSH 上强制使用智能体团队**）；想测试请自行估算价格。

## 人格：调度器 = 指挥，不是看守

你（主 agent）同时是解压器和调度器。一切以你为中心：先解压资源，再调度成员。
成员正常运行就【不打断】——慢可能是好事；应对=【发消息询问】进度，想加派就【直接派】；
15 个成员上限不是限流，是考虑你与成员通信频繁、模型速度慢特意设的。

---

## 第一阶段：解压（先于一切调度）

### 1.1 意图识别（区分压缩包格式）

判断用户资源类型：做 MV / 文案做动画 / 小要求自制 / 其他。按类型决定后续管线；
本 skill 聚焦时间驱动视频，其余类型按需挂对应能力。

### 1.2 意象分析（先于一切风格决策，硬步骤）

**为什么**：直接对"词汇表"选风格会把**载体词误当意象**——歌词里的术语、名词、技术词是【载体】，
不是主题本身。只按字面选视觉，画面会与歌的情感内核错位。风格候选之前，必须先解析"到底在讲什么"。
详细方法与反例见 [`references/imagery-analysis.md`](references/imagery-analysis.md)。

**路径 A —— 素材少（一句话/标题/模糊需求）：主体联想**

```text
1. 抓主体 → 2. 联想 2-3 个候选所指并标出假设（不单方面锁定）
→ 3. 审查缺什么关键资料 → 缺失则联网搜集；必要时向用户确认假设
→ 4. 想文案（打分：表面意思≤50 / 美感≤40 / 多重解读≤10）与演出形式（把需求翻成可视过程）
```

**路径 B —— 素材多（MV：歌+歌词）：深层涵义解析（默认必做，不因"自认为懂了"跳过）**

```text
1. 读完整歌词
2. 客观信号触发联网查证（技术词密集/双关/文化引用/歌名是句子片段/多语言/专辑背景）
   并找**多语种对照**（官方/社区译词）——翻译本身是一次语义解读，能暴露"自以为懂了"的盲区
3. 判别载体词 vs 意象：技术词是载体，追问它象征什么
4. 反例检验：只按字面做，歌的情感还成立吗？不成立 = 字面误读，重做
5. 结合所有信息 → 产出意象分析文档（落盘）
```

**门槛**：风格候选必须能引用意象分析回答"这个风格如何承载主题"；无意象分析 = 风格决策不合格。
意象分析产出同时是"制作分工方案"的输入。

### 1.3 依赖补足（可与 1.4 交叉）

用户资源不足 → 从你的知识库 / 网络搜索补足依赖素材；补完登记进资源清单。

### 1.4 正式解压（五小步，索引表驱动）

```text
(1) 索引表A（资源清单）：登记所有素材——音频(及提取的BPM/onset/频谱/歌词时间轴)、
    素材图、用户意图、补足的依赖。结构表B（段/风格切换点/运镜挂接点）写局部风格时再定。
(2) 总体风格：先想 20-50 种候选 → 筛 5-20 个（标序号）→ 三维推演打分（模型自判，必须引用 §1.2 意象分析）
    （素材贴合/意图贴合/可实现性）→ 在最高分 2-3 个内随机定 1 个最终大体风格；
(3) 局部风格：用表B定位哪部分换风格 → 定 1 个最终风格（决定该部分演出细节）；
(4) 动画细节：文字也是基础元素、要动起来 → 精细排班；
(5) 运镜设计：由动画细节推，规定元素进出场顺序；可反向调整动画细节（上限 3 轮，事不过三）。
```

音频可提取信息（节奏/频谱/歌词时间轴等）= 素材，全部进资源清单。

**风格判定留痕规则**（配合 (2)）：
- 自判依据必须写在 `style_decision.json`（候选 / 入围 / 分数 / 最终选择 + 理由）——判了什么要留痕；
- 不依赖外部评分模型（外部工具仅可作辅助参考，不推荐依赖）；
- 随机数用**确定性来源**（seed），可复现。

### 1.5 软规则：主体风格的颗粒度

```text
主体风格 = 大方向，只锁三样：色调 / 演出主体维度（2D·2.5D·3D·混搭）/ 世界观基调；
其余（镜头语言 / 节奏 / 材质 / 局部风格）分工细化时再定。
避免风格过度统一：主风格锁世界观，局部允许在镜头语言/节奏/材质上变化。
```

## 第二阶段：调度（一切以调度器为中心）

### 2.1 分成员（槽位池，调度器自身不算）

用解压完的素材分出几个成员。**DSH 上必须用智能体团队（`spawn_teammate`）**——子代理（subagent）不够用：
它是一次性/续接的执行体，不提供成员隔离创作、双向通信（可询问 / 可批判）、编号产出与审计。
其他 agent 工具（opencode / Claude Code / Codex 等）的团队机制待收集适配方案（见文末 TODO）。

槽位：最多 **15** 个在跑；有成员完成（文件入队+抽帧到位）→ 释放槽位 → 派新任务。
成员慢不打断（慢可能是好事）→ 发消息询问进度；想加派就直接派。

**权限门（硬规则）**：spawn 成员前，先确认会话文件策略覆盖执行（`danger-full-access` 或至少 `workspace-write`）；
不足则先向用户索要**会话级**权限——成员只继承会话级策略，per-call 放行不传递，无权限时成员跑不了渲染。

### 2.1.5 分工顺序：先元素制作，验收后再分镜制作

分工不只有"按画面分段"，还要**按复杂可复用元素**分工。规则：

```text
第一轮 · 元素制作（先做）
  对象 = 复杂 / 可复用 / 跨片段共享的元素，例如：
    · 角色（造型、表情、动作库）
    · 关键道具 / 装置 / 场景基底
    · 复用材质、粒子系统、字体排版系统
    · 复杂可复用组件（一个要出现十几次的交互/图形）
  判断标准：① 复杂到单 agent 做质量没保证；或 ② 会被多个片段复用
  → 单独派成员制作 → **验收通过后**才进入第二轮

第二轮 · 分镜制作（后做）
  对象 = 各片段的分镜演出（用已验收的元素搭出每段画面）
  → 元素是"零件"，分镜是"用零件组装"；零件没验收就组装 = 返工
```

**为什么先元素后分镜**：
- 可复用元素被多个片段依赖 → 元素改一次，所有用了它的片段都要改；先验收锁定元素，避免连锁返工；
- 复杂元素单 agent 做不好 → 给它独立槽位和完整时间，比塞进片段里赶工质量高；
- 元素验收是**硬门**：元素未过审，不得开始依赖它的分镜制作。

**元素与片段的关系**：元素产出后进入共享素材区（如 `shared/`），分镜成员只读已验收元素，不得自行修改元素（要改 → 回到元素成员）。

**依赖门（硬规则）**：调度器维护**元素-片段依赖表**（如 `deps.json`：片段 → 依赖的元素列表）。
派分镜成员**前**必须检查该片段的全部依赖元素状态 = **已验收**；未验收不得派出——
否则分镜建立在未定型的元素上，元素一改就连锁返工。

---


### 2.2 成员隔离创作（权限契约）

每个成员只读【调度器批准给的素材】：

```text
✅ 允许：调度器分配的片段素材 / 元素素材 + 创作纪律摘要（每镜有运镜/文字要动/确定性）；
❌ 禁止：越权读调度器全量 skill；读其他素材文件；读其他成员的产出；
✅ 产出：按编号入自己的目录（片段如 ch01/，元素如 el-*/）；中途可与调度器沟通细节、可批判调度器；
✅ 每个片段附抽帧（2-3 张代表帧 PNG）；
```

### 2.3 文件审计（调度器审，清单固定）

```text
元素审计清单（第一轮，先过）：
□ 元素完整（该有的部分都在）
□ 可复用性（接口/参数化，不是一次性硬编码）
□ 风格一致（与主风格/局部风格相符）
□ 有抽帧（关键形态 2-3 张）
□ 无越权痕迹

每个片段审计清单（第二轮）：
□ 编号完整无缺号
□ 时间戳与索引表对齐
□ 确定性（同 t 同帧）
□ 风格一致（与局部风格表相符）
□ 有运镜（非静止播放器式）
□ 文字动了（如有文字）
□ 无越权痕迹（只用了批准给的素材）
□ 抽帧到位（2-3 张）
```

未过 → 该成员重做（重新占用槽位，完成后再次审计）；通过 → 释放槽位派新任务。

**重做上限 3 次（事不过三）**：3 次仍未过 → 走降级路径（调度器接手 / 简化该片段需求 / 上报用户），
**不得无限重试**——重试没有上限就是拿时间换噪音。

### 2.4 拼接（两路）

```text
路2：新增微调成员，对每片段运镜动画统一微调；职责单一、并行高、审计易。
路1：调度器分片段时隔一个分一个，后续成员补相邻片段，降低运镜衔接压力。
```

**选择判据**：
- 各片段相对独立（运镜不跨段延续）→ **路2**（统一收口，简单）；
- 片段间运镜需跨段延续（一个镜头跨过段界 / 连贯长镜）→ **路1**（相邻片段由关联成员接手，衔接压力低）；
- 判断不了 → 默认**路2**。

## 第三阶段：成品

所有片段审计通过 + 拼接完成 → 产出成品（MP4）→ 交付时附：资源清单、成员产出目录、
审计记录、已知 MEDIUM/LOW 问题。
