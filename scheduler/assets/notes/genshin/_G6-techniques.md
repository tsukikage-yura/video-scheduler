# 2.5D 分层过场（原神式）复刻 — 完整场景合成 e176–e190

## 一句话结论
**"像过场动画"不是靠把每样东西画得更精细，而是靠四件事同时成立：**
**① 值域分层（远景亮、中景中、近景极暗）② 空气透视（远层低对比 + 雾）③ 单一暖色锚点（全画面只有提灯暖）④ 硬边赛璐璐平涂（不许有柔和渐变过渡）。**
这四条比"画得细"重要一个数量级。任何一条缺失，画面立刻掉回"网页插画"。

---

## 分层架构（所有帧共用）

```
far  平面  ── 天空 + 月亮 + 远山城市       → 最亮、最低对比、blur 2.5px
wall 平面  ── 被 evenodd 打洞的墙体        → 洞口透出 far，墙体最暗
[fog]      ── 空气透视雾（far 与 mid 之间）
mid  平面  ── 柱子 / 地面 / 光柱 / 提灯 / 角色 / 粒子
bloom 平面 ── 只画发光体，两次 blur 叠加
near 平面  ── 前景画框柱 + 焦外光斑         → 近黑、blur 3~7px
[grade]    ── 暗角 multiply + 冷暖 overlay + 暖脚光 + 胶片颗粒
[UI]       ── 对话框 / 选项按钮
```

**关键：分层不只是"画在不同 canvas 上"，而是每层必须有不同的对比度与明度。**
实测亮度（e179）：
| 层 | 平均亮度 |
|---|---|
| 窗口内天空 | ~110 |
| 柱子中段 | ~70 |
| 墙体 | ~27 |
| 地面 | ~17 |
| 前景画框 | ~7 |

近景比远景暗 **15 倍**。这是纵深感的真正来源，不是视差。

## 核心技法

### 1. 哥特尖拱的精确几何
等边尖拱：拱脚间距 = 拱券半径 r。两个圆心分别落在对侧拱脚上。

```js
function archSub(G,x,w,spring,bot){
  var r=w;
  G.moveTo(x,bot); G.lineTo(x,spring);
  G.arc(x+w, spring, r, Math.PI, Math.PI*4/3, false);  // 左弧，圆心在右侧
  G.arc(x,   spring, r, Math.PI*5/3, Math.PI*2, false); // 右弧，圆心在左侧
  G.lineTo(x+w,bot); G.closePath();
}
```
**这是全实验最有价值的一段代码。** 之前用"半圆 + 三角尖"拼，出来像子弹头；换成真正的两段圆弧后立刻变成哥特窗。

### 2. 用 evenodd 在墙上"打洞"
不能先画天空再在墙上画窗户（会盖住天空），也不能用 `destination-out`（会把天空一起擦掉）。正解：**墙 = 一个大矩形 + N 个拱形子路径，用 `fill('evenodd')`**。

```js
wg.beginPath();
wg.rect(-20,-20,W+40,FLOOR+120);
for(...) archSub(wg, x, WIN_W, SPRING, WIN_BOT);  // 注意：不能调 beginPath
wg.fill('evenodd');   // 洞保持透明，天空透出来
```
**坑：`beginPath()` 会清空当前路径。** 所以必须把拱形拆成"只追加子路径"的 `archSub` 和"带 beginPath"的 `archPath` 两个函数。这个 bug 让我debug 了三轮。

### 3. 洞口纵深 = 只压暗墙，不碰洞
用 `source-atop` 沿洞口描粗边，只影响已有像素（墙），洞保持透明：
```js
wg.globalCompositeOperation='source-atop';
wg.strokeStyle='rgba(6,9,22,0.75)'; wg.lineWidth=26;
archPath(wg, x-4, WIN_W+8, SPRING, WIN_BOT); wg.stroke();
```

### 4. 角色：裁剪式边缘光（最关键的角色技法）
**错误做法**：在剪影外侧再描一条亮色带 → 看起来像霓虹灯管。
**正确做法**：把剪影本身当作 clip，在里面填一个横向渐变：
```js
function rimIn(G, path, x0, x1, warm, cool){
  G.save(); G.clip(path); G.globalCompositeOperation='lighter';
  G.fillStyle = lg(G, x0,0, x1,0, [
    [0,    'rgba(150,196,255,'+cool+')'],   // 左：窗户冷光
    [0.13, 'rgba(150,196,255,0)'],
    [0.78, 'rgba(255,206,136,0)'],
    [0.92, 'rgba(255,206,136,'+(warm*0.6)+')'],
    [1,    'rgba(255,200,126,'+warm+')']]);  // 右：提灯暖光
  G.fillRect(x0-40,-520,(x1-x0)+80,560);
  G.restore();
}
```
一次同时得到**左侧冷边缘光 + 右侧暖边缘光**，而且因为被 clip，永远不会溢出轮廓。

### 5. 立绘比例
初版像棋子/雪人，根因是**头太大、剪影太宽**。修正后：
- 头（兜帽）宽度 ≈ 总高 0.22，**总高 460 单位里兜帽只占 ~130**
- 肩宽 ≈ 0.27 × 总高
- 下摆宽 ≈ 0.40 × 总高（不是 0.6）
- 关键：**肩宽 < 下摆宽**，形成梯形；但**肩部斗篷要有弧形下缘**，不能是直线切断
- 眼睛是暗部空洞 + 一点暖色反光，不要画五官

### 6. 赛璐璐平涂（cel shading）
**一条硬边阴影块 > 十条柔和渐变。**
```js
G.clip(cloak);
G.fillStyle='rgba(100,114,160,0.42)';  // 直接填一个不透明色块
G.fill(左侧三分之一形状);
```
再加"光照随高度衰减"：从 y=-120 到 y=20 用 multiply 渐变压暗下半身。

### 7. 空气透视（雾）
雾必须**只加在 far 与 mid 之间**（在 composite 阶段插入），加在 far 平面内部会被墙盖住：
```js
g.drawImage(wall.c,0,0);
if(CFG.fog){ /* 竖直渐变，下浓上淡 */ g.fillRect(...); }
g.drawImage(mid.c,0,0);
```

### 8. 粒子必须分三档远近
- 远（far 层，小、淡、0.42 alpha）→ 只有氛围
- 中（mid 层，大小差异要大，`i%4===0?1.25:(i%3===0?0.62:0.95)`）
- 近（near 层，大、模糊、alpha 0.20，**数量必须少**）
初版近景书页画了 5 片、alpha 0.5，结果变成白色大污渍挡住角色。**近景粒子是最容易毁画面的东西。**

### 9. 冷暖对比 = 全画面只有一个暖源
提灯是唯一暖色。做法：
1. 提灯本体画在 mid 平面（纯色 + 描边）
2. 光晕画在 **bloom 平面**（径向渐变，`lighter` 混合）
3. bloom 平面整体做 **两次** blur（72px + 24px）叠加 → 得到大范围柔光 + 核心亮斑
4. 地面再补一个暖色椭圆（`lighter`）
5. 最后整体加一道底部暖脚光

冷色不需要"画"，靠全局 multiply 暗角 + overlay 蓝调压出来。

### 10. 调色板只需 4 个 stop
所有色调变体（夜/黄昏/月光/余烬）只改 4 个值，画面结构完全复用：
```js
{ top, mid, bot,        // overlay 三段（冷暖基调）
  warm,                 // 底部暖脚光
  vig }                 // multiply 暗角颜色
```

## 踩坑清单（这些坑都很致命）

1. **`destination-out` 会连天空一起擦掉** → 打洞必须用 evenodd。
2. **`beginPath()` 清空多子路径** → 必须拆 archSub / archPath。
3. **opaque fill 会盖住洞口** → 洞口阴影只能用 source-atop。
4. **雾画在 far 内部会被墙盖住** → 雾必须在 composite 阶段、墙之后、mid 之前。
5. **前景光斑 alpha 过高会变灰色圆盘** → 降到 0.065，并给部分染暖色。
6. **近景书页会挡住主角** → 减到 3 片、alpha 0.20。
7. **地面光楔硬边** → 用径向渐变椭圆代替梯形多边形。
8. **画框柱花纹做成半圆会像月牙** → 改成 S 形双曲线 + 圆点 + 尖叶。

## 对 BRIEF 假设的验证结论

BRIEF 假设："几何化 + 平涂 + 分层 + 冷暖 是否足以复刻？"

**结论：基本成立，但需要补一条。**
- 几何化 ✅ 拱窗/柱子/花纹都是纯几何，且比想象中简单
- 平涂 ✅ 硬边色块即可，不需要复杂明暗
- 分层 ✅ 视差不是重点，**明度差**才是重点
- 冷暖 ✅ 单一暖源 + 全局冷压，效果极强

**必须补充的第 5 条：值域控制（value control）。**
原神画面的真正特征不是"元素多"，而是**每一层的明度被严格约束**：
远景不允许超过某个亮度、近景不允许亮于某个亮度。
初版 e176 失败的根本原因就是窗口天空过曝到接近纯白（亮度 200+），
与角色的白衣撞在一起，画面瞬间失去纵深。
**把远景压下去、把近景压到近黑，纵深自己就出来了。**
